# Like2Win User Testing Script

## 📋 **OVERVIEW**

**Feature Under Test:** Raffle Participation Tracking System  
**Test Duration:** 20-30 minutes per user  
**Test Type:** Moderated usability testing  
**Target Users:** Farcaster users familiar with crypto/web3  

---

## 🎯 **TEST OBJECTIVES**

### Primary Goals
1. **Validate User Flow**: Ensure users can successfully complete raffle participation
2. **Identify Friction Points**: Find obstacles in authentication and participation process
3. **Test Value Proposition**: Confirm users understand and value the raffle system
4. **Assess Usability**: Evaluate interface clarity and user experience

### Success Metrics
- **Task Completion Rate**: >85% of users complete core tasks
- **Time to First Participation**: <5 minutes from landing
- **User Satisfaction**: >4/5 average rating
- **Error Recovery**: Users can recover from errors without assistance

---

## 👤 **PARTICIPANT CRITERIA**

### Primary Audience (80% of participants)
- Active Farcaster users (>1 month)
- Basic crypto/web3 knowledge
- Has connected wallet to dApps before
- Familiar with "like/comment/recast" mechanics

### Secondary Audience (20% of participants)
- New to Farcaster (<1 month)
- Limited crypto experience
- Curious about web3 but hesitant

### Exclusion Criteria
- No Farcaster account
- Complete crypto/web3 beginners
- Under 18 years old

---

## 📝 **PRE-TEST CHECKLIST**

### Environment Setup
- [ ] Test environment is running and stable
- [ ] Test data is seeded (active raffle, test posts)
- [ ] Recording software is ready (Zoom, Loom, or similar)

### Materials Needed
- [ ] Test script (this document)
- [ ] Observation sheet for each participant
- [ ] Post-test survey link
- [ ] Compensation ready (if applicable)
- [ ] Emergency contact for technical issues

## 🚀 **TEST SCRIPT**

### **Introduction (3-5 minutes)**

**Moderator Says:**

> "Hi [Name], thanks for participating in our user test today. I'm [Your Name] and I'll be guiding you through testing a new feature called Like2Win - it's a raffle system that works with Farcaster.
> 
> **What we're testing:** A new way to participate in raffles by engaging with Farcaster posts
> 
> **What we're NOT testing:** You! We're testing the product, so any issues are our fault, not yours.
> 
> **Think aloud:** Please share your thoughts as you go - what you're thinking, what's confusing, what you expect to happen.
> 
> **No wrong answers:** Do whatever feels natural to you.
> 
> **Questions:** Feel free to ask questions, but I might ask you to try figuring it out first to see how intuitive it is.
> 
> **Recording:** I'll be recording this session to review later. Is that okay?"

**Pre-Test Questions:**
1. How long have you been using Farcaster?
2. Have you participated in crypto raffles or giveaways before?
3. What's your experience with connecting wallets to websites?
4. What would you expect from a "raffle participation" feature?

---

### **Task 1: First Impression & Landing (5 minutes)**

**Setup:** Navigate to homepage (not logged in)

**Task:** "Imagine you heard about Like2Win from a friend. You're visiting for the first time. Take a look around and tell me what this is about."

**Observe:**
- [ ] User understands the value proposition within 30 seconds
- [ ] User identifies how to get started
- [ ] User notices authentication options
- [ ] User understands the raffle concept

**Follow-up Questions:**
- "What would you do next if you were interested?"
- "What questions do you have about how this works?"
- "What concerns you most about this?"

**Success Criteria:**
- User understands it's about Farcaster raffle participation
- User can identify next steps
- User expresses interest or curiosity

---

### **Task 2: Authentication Process (5-7 minutes)**

**Task:** "Let's say you want to try this out. Go ahead and connect your account."

**Observe:**
- [ ] User chooses between wallet/Farcaster auth without confusion
- [ ] Authentication flow completes successfully
- [ ] User understands what permissions they're granting
- [ ] User sees confirmation of successful authentication

**If Issues Arise:**
- Note exact error messages
- Observe user's reaction and recovery attempts
- Help only if user is completely stuck

**Follow-up Questions:**
- "How did that feel compared to other crypto apps?"
- "What would you expect to see next?"
- "Any concerns about what you just connected?"

**Success Criteria:**
- Authentication completes within 2 minutes
- User doesn't express confusion about the process
- User feels confident about security

---

### **Task 3: Understanding Current Status (3-5 minutes)**

**Task:** "Now that you're connected, explore your current status in the raffle."

**Observe:**
- [ ] User navigates to raffle status/dashboard
- [ ] User understands their current ticket count
- [ ] User comprehends raffle timing and prize info
- [ ] User grasps their win probability and ranking

**Prompt if stuck:** "Look for information about your current position"

**Follow-up Questions:**
- "What do you understand about your current status?"
- "What would you need to do to improve your chances?"
- "How clear is the raffle timeline to you?"

**Success Criteria:**
- User finds and understands key status information
- User can explain how to earn more tickets
- User shows engagement with the competitive aspect

---

### **Task 4: Understanding Participation Requirements (3-5 minutes)**

**Task:** "Figure out what you need to do to participate in this raffle."

**Observe:**
- [ ] User identifies follow requirement for @Like2Win
- [ ] User understands engagement requirements (like/comment/recast)
- [ ] User notices different requirements based on tip allowance status
- [ ] User comprehends how tickets are earned

**Probe:** "What's the difference between users with and without tip allowance?"

**Follow-up Questions:**
- "How do you feel about the participation requirements?"
- "Do these requirements seem fair to you?"
- "What would motivate you to actually do these actions?"

**Success Criteria:**
- User clearly understands participation requirements
- User doesn't express frustration with requirements
- User sees value in the engagement model

---

### **Task 5: Exploring Leaderboard & Competition (3-5 minutes)**

**Task:** "Check out how you compare to other participants."

**Observe:**
- [ ] User finds and navigates to leaderboard
- [ ] User understands ranking system
- [ ] User identifies their position (if participating)
- [ ] User comprehends competitive dynamics

**Follow-up Questions:**
- "How does seeing other participants make you feel?"
- "What would motivate you to try to rank higher?"
- "Is there anything surprising about the leaderboard?"

**Success Criteria:**
- User engages positively with competitive aspect
- User understands their relative position
- User expresses motivation to participate more

---

### **Task 6: Simulated Participation (if possible)**

**Note:** This may be simulated since we can't control actual Farcaster engagement

**Task:** "If you saw an official Like2Win post in your Farcaster feed, walk through what you would do."

**Observe:**
- [ ] User explains they would like/comment/recast
- [ ] User understands the connection between engagement and tickets
- [ ] User expects to see status updates after participation
- [ ] User grasps the timing aspects

**Follow-up Questions:**
- "What would you expect to happen after you engage with a post?"
- "How would you verify that your participation counted?"
- "What would make you want to engage with more posts?"

**Success Criteria:**
- User clearly connects off-platform action to on-platform reward
- User has realistic expectations about participation flow
- User expresses willingness to engage with content

---

### **Task 7: Frame Interaction (if available)**

**Task:** "Check out this Farcaster frame for the raffle."

**Setup:** Show raffle status frame or participation frame

**Observe:**
- [ ] User understands frame functionality
- [ ] User successfully interacts with frame buttons
- [ ] User sees value in frame vs. main website
- [ ] User's expectations align with frame capabilities

**Follow-up Questions:**
- "How useful is this compared to the main website?"
- "When would you use the frame vs. the website?"
- "What would you want to see added to the frame?"

**Success Criteria:**
- User successfully interacts with frames
- User sees frames as valuable addition
- User understands frame limitations

---

## 📊 **POST-TEST ACTIVITIES**

### **Wrap-up Questions (3-5 minutes)**

1. **Overall Experience**
   - "How would you describe Like2Win to a friend?"
   - "What's the most compelling part of this for you?"
   - "What's your biggest concern or hesitation?"

2. **Likelihood to Use**
   - "On a scale of 1-10, how likely are you to actually use this?"
   - "What would increase that likelihood?"
   - "What would be a dealbreaker for you?"

3. **Improvements**
   - "What's the most confusing part that needs fixing?"
   - "What feature are you missing?"
   - "If you could change one thing, what would it be?"

4. **Trust & Security**
   - "How do you feel about the security of this system?"
   - "What would make you more comfortable participating?"
   - "Any concerns about connecting your accounts?"

### **Post-Test Survey**

**Send participants a brief survey covering:**

**Usability (1-5 scale):**
- How easy was it to understand what Like2Win does?
- How easy was it to connect your account?
- How clear were the participation requirements?
- How intuitive was the navigation?
- How trustworthy does the platform feel?

**Value Proposition (1-5 scale):**
- How valuable is this concept to you?
- How fair do the raffle mechanics seem?
- How motivating is the competitive aspect?
- How likely are you to recommend this to others?

**Open-Ended:**
- What's the best thing about Like2Win?
- What's the most frustrating thing?
- What features are missing?
- Any other feedback?

## 🎯 **OBSERVATION GUIDE**

### **What to Watch For**

**Navigation Patterns:**
- Do users find key information quickly?
- Where do they get stuck or confused?
- Do they use expected paths or find shortcuts?

**Emotional Reactions:**
- Moments of delight or excitement
- Signs of frustration or confusion
- Trust signals that resonate
- Skepticism or concern

**Language & Mental Models:**
- How do they describe what they're seeing?
- What terminology confuses them?
- What expectations do they bring?

**Error Recovery:**
- How do they react to errors or unexpected states?
- Do they retry or give up?
- Can they self-recover?

### **Critical Success Moments**

1. **"Aha" Moment**: When user understands the value proposition
2. **Trust Moment**: When user feels comfortable connecting accounts
3. **Engagement Moment**: When user sees personal benefit
4. **Motivation Moment**: When user wants to participate more

### **Red Flags**

- User can't complete authentication within 5 minutes
- User doesn't understand participation requirements after explanation
- User expresses strong security concerns
- User shows no interest in competitive aspects
- User can't find critical information (tickets, requirements, status)

## 📈 **SUCCESS METRICS TRACKING**

### **Quantitative Metrics**

| Metric | Target | Measurement |
|--------|--------|-------------|
| Task Completion Rate | >85% | # completed / # attempted |
| Time to Authentication | <3 min | Time from landing to auth complete |
| Time to Understanding | <5 min | Time until user explains concept correctly |
| Error Rate | <2 per user | Number of errors/confusion points |
| SUS Score | >68 | System Usability Scale questionnaire |

### **Qualitative Indicators**

**Excellent (5/5):**
- User completes all tasks smoothly
- Expresses excitement about concept
- Can explain value to others
- Wants to use immediately

**Good (4/5):**
- Completes most tasks with minor issues
- Understands and appreciates concept
- Would likely use with small improvements
- Generally positive experience

**Acceptable (3/5):**
- Completes core tasks with help
- Understands concept but has concerns
- Might use if issues are addressed
- Mixed feedback

**Poor (2/5):**
- Struggles with multiple tasks
- Confused about core concept
- Significant usability issues
- More negative than positive

**Failure (1/5):**
- Cannot complete core tasks
- Doesn't understand value proposition
- Major usability or trust issues
- Would not recommend

## 🔧 **TROUBLESHOOTING GUIDE**

### **Common Technical Issues**

**Authentication Fails:**
- Check network connection
- Try different browser
- Clear cache/cookies
- Use backup test account

**Frame Not Loading:**
- Verify frame endpoint is working
- Check Farcaster integration
- Try different frame URL
- Use mobile device if desktop fails

**Slow Performance:**
- Check server status
- Monitor network latency
- Switch to backup environment
- Document performance issues

### **Participant Issues**

**User Confused:**
- Give them time to explore
- Ask what they expect to see
- Avoid leading questions
- Document specific confusion points

**User Frustrated:**
- Acknowledge the frustration
- Ask what would help
- Consider shortening session
- Ensure they feel heard

**Technical Difficulties:**
- Have backup device ready
- Consider remote screen sharing
- Document exact error messages
- Continue with manual walkthrough if needed
